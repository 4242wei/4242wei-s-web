# Outlook 访谈日历同步

本模块只读取 Outlook 发布的 ICS 日历，不使用 Microsoft Graph、OAuth 或浏览器登录状态，也没有邮件、联系人、参会者、附件、发送、回复或编辑权限。

## 推荐连接方式

1. 在 Outlook 网页版进入“设置 → 日历 → 共享日历 → 发布日历”。
2. 选择需要同步的日历。可以发布详细信息，但系统只会显示能够与当前专家库中的姓名匹配的日程；其他普通会议会被过滤。
3. 点击“发布”并复制 **ICS** 地址，不要复制 HTML 地址。
4. 在网页“专家组合 → 访谈日程 → Outlook 未连接”中粘贴，点击“保存并测试”。

发布 ICS 是 Outlook 账户侧的持久授权，必须由账户持有人亲自完成。需要撤销时，在同一 Outlook 设置页点击“取消发布”。

## 数据边界

- ICS 地址保存在 `data/outlook_calendar_config.json`，权限为 `0600`，页面保存后不再回显。
- 同步事件先保存在独立的 `data/outlook_calendar_cache.json`。经严格匹配后，会由确定性后端步骤写入对应专家的访谈记录；DeepSeek 本身没有写权限。
- 写入以哈希事件 ID 幂等去重，并先尝试关联同一专家 15 分钟内的已有手工访谈。关联时不覆盖备注、访谈人、转录、摘要、完成状态等手工字段。
- 新建的未来首次访谈把专家状态设为“安排中”；已有历史访谈后的未来日程设为“追访中”。不会仅因预约时间经过就自动标记“已完成访谈”。
- 早于该专家在系统中建档时间的旧 Outlook 日程不追溯补建。
- 每次拉取后先比较事件内容指纹。标题、时间、地点、说明和专家清单均未变化时直接复用上次结果，不重复调用模型。
- 新增、删除或修改专家后会绕过一次 Outlook 条件缓存，重新核对完整日历；之后恢复增量模式。
- 只有新增或发生变化的脱敏事件才会批量交给 DeepSeek，并只允许返回当前专家库中的专家 ID。姓名片段、公司简称、职位、专家序号及访谈语义可综合核对。
- 模型结果还必须能在事件原文中找到姓名、公司、专家序号或可靠身份片段；仅凭“专家访谈”字样不能猜测专家。
- 未匹配事件只累计过滤数量，不保存标题、地点、描述或其他逐条信息，也不会出现在网页中。
- 原始事件 UID 只存 SHA-256 摘要。
- 邮箱、网址、会议链接、电话号码和 HTML 会在本地移除。
- DeepSeek 只接收脱敏后的事件字段和最小专家清单；高置信度不足就直接过滤，不显示为访谈。
- 后台默认每 4 小时检查一次，并使用 ETag / Last-Modified；失败时保留上次正常结果。手动点击刷新不受定时周期影响。
- 同步时会按事件 UID 以及“开始时间＋结束时间＋标题＋地点”双重去重；匹配专家后再和已有访谈时间比较，显示第几次沟通。已有同时间访谈只标记为已有记录，不重复新增。

## 语音转录关联

- 同一个四小时后台任务会扫描语音转录标题、原文件名和会议日期；不会把转录正文或音频交给模型。
- 只有唯一姓名或公司命中、日期唯一对应一条未关联访谈、且不是重复上传时，才自动填入该访谈的 `transcript_id`。
- 同日期、同原文件名和同文件大小的重复上传只标记“疑似重复”，不会增加访谈次数。
- 本地无法唯一判断时，DeepSeek 最多接收标题、日期以及同日候选专家的姓名和公司；结果只作为建议，不能自动写入。
- 关联建议保存在独立的 `data/expert_interview_link_cache.json`，失败不会影响专家库、访谈记录或网页运行。

## 本地文件回退

若组织禁用了日历发布，可在 Outlook 导出 `.ics` 文件，再通过同一设置区“导入 .ics”读取。文件导入仍然只更新独立缓存，不会改专家档案，但不会自动刷新。

## 验证与回滚

- 使用合成 ICS 测试 UTC 到北京时间转换、敏感字段脱敏、官方域名限制、文件权限和本地专家匹配。
- 连接新地址时先下载并解析成功，之后才替换旧配置；验证失败不会覆盖旧配置或缓存。
- 代码级回滚快照位于 `backups/startup-guard/`。
